    25→## 1. Architecture Overview
    26→
    27→### High-Level Architecture
    28→
    29→```
    30→┌─────────────────────────────────────────────────────────────┐
    31→│                     Electron Shell (Tauri v2)               │
    32→│  ┌───────────────────────────────────────────────────────┐  │
    33→│  │              Next.js 16 App (SSR + Client)            │  │
    34→│  │  ┌─────────────┐  ┌──────────────┐  ┌─────────────┐  │  │
    35→│  │  │  Settings   │  │  Profiles    │  │  Execution  │  │  │
    36→│  │  │  Engine     │  │  Manager     │  │  Engine     │  │  │
    37→│  │  └──────┬──────┘  └──────┬───────┘  └──────┬──────┘  │  │
    38→│  │         │                │                  │         │  │
    39→│  │  ┌──────┴────────────────┴──────────────────┴──────┐  │  │
    40→│  │  │              Zustand State Store                │  │  │
    41→│  │  └─────────────────────┬─────────────────────────┘  │  │
    42→│  └────────────────────────┼────────────────────────────┘  │
    43→│                           │                                │
    44→│  ┌────────────────────────┴────────────────────────────┐  │
    45→│  │           PowerShell Bridge (IPC Layer)             │  │
    46→│  │  • Script generation  • Execution  • Output capture │  │
    47→│  └─────────────────────────────────────────────────────┘  │
    48→└─────────────────────────────────────────────────────────────┘
    49→```
    50→
    51→### Core Design Decisions
    52→
    53→| Decision | Choice | Rationale |
    54→|----------|--------|-----------|
    55→| **Framework** | Next.js 16 (App Router) | Modern React, SSR for fast initial load, API routes for PS bridge |
    56→| **Desktop Shell** | Tauri v2 | Rust-based, ~3MB binary, native PS execution, no Chromium bundling like Electron |
    57→| **State** | Zustand + persist middleware | Lightweight, no boilerplate, built-in persistence to localStorage/JSON |
    58→| **UI Library** | shadcn/ui (Radix + Tailwind) | Accessible, composable, dark theme out of the box |
    59→| **Styling** | Tailwind CSS 4 | Utility-first, design token support, CSS custom properties for theming |
    60→| **Icons** | Lucide React | Consistent, tree-shakeable, 1500+ icons |
    61→| **Data Source** | Static JSON catalog + script parser | Settings catalog is generated from PS1 at build time; runtime reads it |
    62→| **Config Format** | JSON (compatible with PS1's -ConfigFile) | Direct interoperability with existing script |
    63→
    64→### Two Deployment Modes
    65→
    66→1. **Tauri Desktop App** (primary) — native Windows app with direct PowerShell execution
    67→2. **Web App** (secondary) — runs in browser; generates scripts for download but cannot execute directly

   101→### Our Unique Selling Points (no competitor has ALL of these)
   102→
   103→1. **Per-setting granularity with tooltips** — Every one of 185 settings can be individually toggled, each with a human-readable description, safety badge, and technical detail tooltip
   104→2. **3-tier safety classification** — Visual badges (Safe=green, Moderate=amber, Risky=red) with risky defaults OFF
   105→3. **Granular per-setting undo** — Not all-or-nothing. Undo specific changes from a selection list
   106→4. **Named profiles** — Save/load named configurations with descriptions ("Gaming Rig", "Office Laptop", "Kiosk")
   107→5. **Real-time change preview** — Before applying, see exactly what will change (registry paths, values, services) in a diff-like view
   108→6. **5-browser hardening** — Chrome, Edge, Firefox, Brave, Opera with extension deployment + enterprise policies
   109→7. **Hardware-aware execution** — SSD/HDD detection, laptop/desktop, RAM-aware settings (from the PS1 script)
   110→8. **Modern web GUI** — Beautiful, responsive, dark-themed React app (competitors use WPF or console)

   114→## 3. Data Model
   115→
   116→### Core Types
   117→
   118→```typescript
   119→// ─── Safety Classification ───
   120→type SafetyLevel = 'Safe' | 'Moderate' | 'Risky';
   121→
   122→// ─── Section Definition ───
   123→interface Section {
   124→  id: string;              // "Privacy", "Debloat", "EdgeHardening", etc.
   125→  name: string;            // Display name: "Privacy and Telemetry"
   126→  description: string;     // Section-level tooltip/description
   127→  icon: string;            // Lucide icon name: "shield", "trash2", "globe", etc.
   128→  order: number;           // Display order (1-18)
   129→  category: SectionCategory;
   130→  safetySummary: {
   131→    safe: number;
   132→    moderate: number;
   133→    risky: number;
   134→    total: number;
   135→  };
   136→  requiresReboot: boolean;
   137→  requiresNetwork: boolean; // Needs internet (e.g., Winget, Office)
   138→  win11Only?: boolean;
   139→  win10Only?: boolean;
   140→}
   141→
   142→type SectionCategory = 
   143→  | 'privacy'      // Privacy, EdgeHardening, BrowserHardening
   144→  | 'cleanup'      // Debloat, DiskCleanup, ScheduledTasks, WindowsFeatures
   145→  | 'performance'  // Performance, ServiceStartup, Gaming
   146→  | 'security'     // Security, Network, WindowsUpdate
   147→  | 'customize'    // ExplorerUI, OneDrive, FinalTouches
   148→  | 'install';     // Winget, OfficeActivation
   149→
   150→// ─── Individual Setting ───
   151→interface Setting {
   152→  id: string;              // "Privacy_AllowTelemetry", "Debloat_Copilot", etc.
   153→  sectionId: string;       // Foreign key to Section.id
   154→  name: string;            // Human-readable name
   155→  description: string;     // Tooltip description (from PS1 -Description param)
   156→  safetyLevel: SafetyLevel;
   157→  type: SettingType;       // What kind of change this is
   158→  action: string;          // Technical action: "HKLM\...\AllowTelemetry = 0"
   159→  
   160→  // State
   161→  enabled: boolean;        // Whether this setting is toggled ON
   162→  applied: boolean;        // Whether this has been applied to the system
   163→  skipped: boolean;        // Whether it was skipped (already set / risky blocked)
   164→  failed: boolean;         // Whether it failed to apply
   165→  
   166→  // Optional context
   167→  registryPath?: string;   // For registry settings
   168→  registryName?: string;
   169→  registryValue?: string | number;
   170→  registryType?: 'DWord' | 'QWord' | 'String' | 'ExpandString';
   171→  taskPath?: string;       // For scheduled task settings
   172→  taskName?: string;
   173→  appxName?: string;       // For AppX bloatware
   174→  featureName?: string;    // For Windows features
   175→  wingetId?: string;       // For Winget packages
   176→  serviceName?: string;   // For service settings
   177→  
   178→  // Undo
   179→  undoCommand?: string;    // PowerShell command to revert
   180→  undoDescription?: string;
   181→}
   182→
   183→type SettingType = 
   184→  | 'registry' 
   185→  | 'scheduled-task' 
   186→  | 'appx-package'
   187→  | 'windows-feature'
   188→  | 'winget-package'
   189→  | 'chocolatey-package'
   190→  | 'service'
   191→  | 'hosts-entry'
   192→  | 'dns-config'
   193→  | 'power-plan'
   194→  | 'browser-policy'
   195→  | 'browser-extension'
   196→  | 'custom';             // For anything else
   197→
   198→// ─── Profile (Saved Configuration) ───
   199→interface Profile {
   200→  id: string;              // UUID
   201→  name: string;            // "Gaming Rig", "Office Laptop", "Kiosk Mode"
   202→  description: string;     // "Optimized for gaming with privacy preserved"
   203→  createdAt: string;       // ISO 8601
   204→  updatedAt: string;
   205→  isBuiltIn: boolean;      // true for factory presets
   206→  
   207→  // The actual configuration
   208→  sections: {
   209→    [sectionId: string]: {
   210→      enabled: boolean;    // Is this section included?
   211→      settings: {
   212→        [settingId: string]: boolean;  // true = ON, false = toggled OFF
   213→      };
   214→    };
   215→  };
   216→  
   217→  // Metadata
   218→  tag?: string;            // Optional tag for filtering
   219→  author?: string;
   220→  version?: string;        // PS1 version this profile was created for
   221→}
   222→
   223→// ─── Execution State ───
   224→interface ExecutionState {
   225→  status: 'idle' | 'preflight' | 'running' | 'paused' | 'completed' | 'failed' | 'cancelled';
   226→  currentSection: string | null;
   227→  currentSetting: string | null;
   228→  progress: {
   229→    totalSettings: number;
   230→    appliedSettings: number;
   231→    skippedSettings: number;
   232→    failedSettings: number;
   233→    percentComplete: number;
   234→  };
   235→  logs: LogEntry[];
   236→  startTime: string | null;
   237→  endTime: string | null;
   238→  sectionStats: {
   239→    [sectionId: string]: {
   240→      duration: number;    // milliseconds
   241→      changed: number;
   242→      skipped: number;
   243→      failed: number;
   244→    };
   245→  };
   246→}
   247→
   248→interface LogEntry {
   249→  timestamp: string;
   250→  level: 'info' | 'success' | 'warn' | 'error';
   251→  section?: string;
   252→  settingId?: string;
   253→  message: string;
   254→}
   255→
   256→// ─── Pre-flight Check Results ───
   257→interface PreflightResult {
   258→  isAdmin: boolean;
   259→  osVersion: string;
   260→  osBuild: number;
   261→  isWin11: boolean;
   262→  chassisType: 'Laptop' | 'Desktop' | 'Unknown';
   263→  bootDriveType: 'SSD' | 'HDD' | 'Unknown';
   264→  totalRamGB: number;
   265→  internetConnected: boolean;
   266→  freeDiskSpaceGB: number;
   267→  pendingReboot: boolean;
   268→  batteryLevel?: number;
   269→  onAcPower?: boolean;
   270→  defenderExcluded: boolean;
   271→  restorePointEnabled: boolean;
   272→}
   273→
   274→// ─── Undo Entry ───
   275→interface UndoEntry {
   276→  id: string;
   277→  settingId: string;
   278→  sectionId: string;
   279→  description: string;
   280→  undoCommand: string;
   281→  type: SettingType;
   282→  appliedAt: string;
   283→  selected: boolean;      // For granular undo selection
   284→}
   285→
   286→// ─── Search & Filter State ───
   287→interface FilterState {
   288→  searchQuery: string;
   289→  safetyFilter: SafetyLevel | 'all';
   290→  categoryFilter: SectionCategory | 'all';
   291→  statusFilter: 'all' | 'enabled' | 'disabled' | 'applied' | 'risky';
   292→  sectionFilter: string | 'all';  // Section ID or 'all'
   293→}
   294→```

   723→## 7. PowerShell Integration
   724→
   725→### Architecture: How the GUI Drives the Script
   726→
   727→The GUI does NOT modify the PS1 script directly. Instead, it generates a **JSON configuration file** that the existing `-ConfigFile` parameter consumes. The PS1 script is the single source of truth for all optimizations.
   728→
   729→```
   730→┌──────────────┐     JSON Config      ┌──────────────────┐
   731→│   Next.js    │ ──────────────────→  │  WinPostInstall  │
   732→│   GUI        │                      │  .ps1 -ConfigFile │
   733→│              │ ←──────────────────  │                  │
   734→│              │   Streaming Output   │                  │
   735→└──────────────┘                      └──────────────────┘
   736→```
   737→
   738→### Flow: Configure → Preview → Generate → Execute
   739→
   740→#### Step 1: UI Configuration → JSON Config
   741→
   742→The UI state (Zustand stores) is converted to a JSON config file compatible with the PS1 script's `-ConfigFile` format:
   743→
   744→```typescript
   745→// lib/config-generator.ts
   746→function generateConfig(state: SettingsStoreState): WinPostInstallConfig {
   747→  const config: WinPostInstallConfig = {
   748→    Sections: [],
   749→    AppList: [],
   750→    BloatwareList: [],
   751→    SettingOverrides: {},   // NEW: settings toggled OFF
   752→    AllowRisky: false,
   753→  };
   754→
   755→  // 1. Add sections that have any enabled settings
   756→  for (const sectionId of ALL_SECTION_IDS) {
   757→    const sectionSettings = state.settings.filter(
   758→      s => s.sectionId === sectionId && s.enabled
   759→    );
   760→    if (sectionSettings.length > 0) {
   761→      config.Sections.push(sectionId);
   762→    }
   763→  }
   764→
   765→  // 2. Add settings toggled OFF (to pass to PS1's SettingOverrides)
   766→  for (const setting of state.settings) {
   767→    if (!setting.enabled) {
   768→      config.SettingOverrides[setting.id] = true;
   769→    }
   770→  }
   771→
   772→  // 3. Winget app list
   773→  config.AppList = state.wingetApps
   774→    .filter(a => a.selected)
   775→    .map(a => ({ ID: a.id, Name: a.name }));
   776→
   777→  // 4. Bloatware list
   778→  config.BloatwareList = state.bloatwareItems
   779→    .filter(b => b.selected)
   780→    .map(b => b.pattern);
   781→
   782→  // 5. Risky settings
   783→  config.AllowRisky = state.allowRisky;
   784→
   785→  return config;
   786→}
   787→```
   788→
   789→#### Step 2: Script Generation (for Export/Preview)
   790→
   791→For users who want to download a standalone script:
   792→
   793→```typescript
   794→// lib/script-generator.ts
   795→function generateScript(config: WinPostInstallConfig): string {
   796→  // Option A: Generate a wrapper .ps1 that calls WinPostInstall.ps1 with -ConfigFile
   797→  // Option B: Generate a self-contained script with only selected settings inlined
   798→  // Option A is preferred — keeps PS1 as single source of truth
   799→  
   800→  const configJson = JSON.stringify(config, null, 2);
   801→  const configB64 = Buffer.from(configJson).toString('base64');
   802→  
   803→  return `
   804→# WinPostInstall - Generated Configuration Wrapper
   805→# Generated by WinPostInstall GUI on ${new Date().toISOString()}
   806→$ConfigJson = [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String("${configB64}"))
   807→$ConfigPath = "$env:TEMP\\WinPostInstall-Config.json"
   808→$ConfigJson | Set-Content -Path $ConfigPath -Encoding UTF8
   809→& "${PS1_SCRIPT_PATH}" -ConfigFile $ConfigPath
   810→Remove-Item $ConfigPath -Force -ErrorAction SilentlyContinue
   811→`.trim();
   812→}
   813→```

   822→async fn execute_powershell(

   834→    if allow_risky {
   835→        cmd.arg("-AllowRisky");
   836→    }
   837→    // Spawn and return handle for streaming output
   838→    // ...
   839→}
   840→```
   841→
   842→#### Step 4: Execution (Web Mode — No Direct Execution)
   843→
   844→In web mode, the app can only:
   845→1. Generate the config JSON for download
   846→2. Generate a wrapper .bat + .ps1 for download
   847→3. Show the user instructions to run it
   848→
   849→```typescript
   850→// lib/bridge.ts — Web mode fallback
   851→function downloadExecutionPackage(config: WinPostInstallConfig) {
   852→  const files = {
   853→    'WinPostInstall-Config.json': JSON.stringify(config, null, 2),
   854→    'Run-WinPostInstall.bat': generateBatLauncher(),
   855→    'WinPostInstall.ps1': PS1_SCRIPT_SOURCE,  // bundled
   856→  };
   857→  
   858→  // Create ZIP and trigger download
   859→  downloadZip(files, 'WinPostInstall-Package.zip');
   860→}
   861→```
   862→
   863→#### Step 5: Output Capture & Streaming
   864→
   865→The PowerShell bridge captures three streams:
   866→- **stdout** → parsed into structured log entries
   867→- **stderr** → error entries
   868→- **exit code** → success/failure
   869→
   870→```typescript
   871→// Parse PS1 output into structured entries
   872→function parsePsOutput(line: string): LogEntry | null {
   873→  // Match patterns from the PS1 script:
   874→  // [OK] Registry: HKLM\...\AllowTelemetry = 0
   875→  // [WARN] Something
   876→  // [ERROR] Failed to set...
   877→  // SKIPPED (risky): ...
   878→  // SKIPPED (already set): ...
   879→  
   880→  if (line.includes('[OK]')) return { level: 'success', ... };
   881→  if (line.includes('[WARN]')) return { level: 'warn', ... };
   882→  if (line.includes('[ERROR]')) return { level: 'error', ... };
   883→  if (line.includes('SKIPPED')) return { level: 'info', ... };
   884→  return { level: 'info', message: line };
   885→}
   886→```
   887→
   888→### Build-Time: Settings Catalog Extraction
   889→
   890→A build-time script parses the PS1 to extract all settings metadata:
   891→
   892→```typescript
   893→// scripts/parse-ps1-catalog.ts
   894→interface ParsedSetting {
   895→  settingId: string;
   896→  section: string;
   897→  safetyLevel: SafetyLevel;
   898→  description: string;
   899→  action: string;       // e.g., "HKLM\SOFTWARE\...\AllowTelemetry = 0"
   900→  type: 'registry' | 'scheduled-task';
   901→  registryPath?: string;
   902→  registryName?: string;
   903→  registryValue?: string;
   904→}
   905→
   906→// Parse all Set-Registry calls:
   907→// Set-Registry -Path "HKLM:\..." -Name "AllowTelemetry" -Value 0 
   908→//   -Type DWord -SafetyLevel "Safe" 
   909→//   -Description "Stops Windows telemetry" 
   910→//   -SettingID "Privacy_AllowTelemetry"
   911→//
   912→// → Extract: { id, section, safety, desc, action, path, name, value }
   913→
   914→// Parse all Disable-AppTask calls similarly
   915→```
   916→
   917→This runs at build time and generates `src/data/settings-catalog.ts`, which the UI imports as static data.

  1133→### Zustand Stores
  1134→
  1135→#### Settings Store (Core State)
  1136→
  1137→```typescript
  1138→// stores/settings-store.ts
  1139→interface SettingsStore {
  1140→  // All settings (loaded from catalog at startup)
  1141→  settings: Map<string, Setting>;
  1142→  
  1143→  // Section-level toggle state
  1144→  sections: Map<string, { enabled: boolean }>;
  1145→  
  1146→  // Risky settings gate
  1147→  allowRisky: boolean;
  1148→  
  1149→  // Actions
  1150→  toggleSetting: (id: string) => void;
  1151→  toggleSection: (id: string) => void;
  1152→  enableAllSafe: () => void;
  1153→  enableAllSafeModerate: () => void;
  1154→  enableAllIncludingRisky: () => void;
  1155→  resetToDefaults: () => void;
  1156→  applyProfile: (profile: Profile) => void;
  1157→  
  1158→  // Computed (via selectors)
  1159→  getSettingsBySection: (sectionId: string) => Setting[];
  1160→  getEnabledSettingsCount: () => number;
  1161→  getSafetySummary: (sectionId: string) => { safe: number; moderate: number; risky: number };
  1162→}
  1163→```
  1164→
  1165→#### Profile Store
  1166→
  1167→```typescript
  1168→// stores/profile-store.ts
  1169→interface ProfileStore {

  1173→  // Actions
  1174→  saveProfile: (name: string, description: string) => void;
  1175→  loadProfile: (id: string) => void;
  1176→  duplicateProfile: (id: string) => void;
  1177→  deleteProfile: (id: string) => void;
  1178→  exportProfile: (id: string) => string; // JSON string

  1190→  // Actions

  1192→  pauseExecution: () => void;

  1199→
  1200→### Persistence
  1201→
  1202→- **Settings store**: Persisted to `localStorage` (auto-save on every toggle)
  1203→- **Profile store**: Persisted to `localStorage` + exportable as JSON files
  1204→- **Execution store**: NOT persisted (ephemeral, per-session)
  1205→- **Tauri mode**: Can persist to `%APPDATA%\WinPostGUI\` instead of localStorage

  1380→The existing PS1 script already supports `-ConfigFile` with JSON. To fully support the GUI, we need to add one enhancement:
  1381→
  1382→### New: `-SettingOverrides` support in config JSON
  1383→
  1384→Currently the PS1 script has `$script:SettingOverrides` populated only by the interactive menu. To support GUI-driven overrides via config file:
  1385→
  1386→```json
  1387→{
  1388→  "Sections": ["Privacy", "Debloat"],
  1389→  "SettingOverrides": {
  1390→    "Privacy_DisableCortana": true,
  1391→    "Debloat_WindowsCamera": true
  1392→  },
  1393→  "AllowRisky": false,
  1394→  "AppList": [...],
  1395→  "BloatwareList": [...]
  1396→}
  1397→```
  1398→
  1399→This requires a small PS1 modification to read `SettingOverrides` from the config file:
  1400→
  1401→```powershell
  1402→# In the -ConfigFile loading block, add:
  1403→if ($config.SettingOverrides) {
  1404→    foreach ($key in $config.SettingOverrides.PSObject.Properties) {
  1405→        if ($key.Value -eq $true) {
  1406→            $script:SettingOverrides[$key.Name] = $true
  1407→        }
  1408→    }
  1409→}
  1410→if ($config.AllowRisky -eq $true) {
  1411→    $script:AllowRisky = $true
  1412→}
  1413→```
  1414→
  1415→This is a **15-line change** to the PS1 script and maintains full backward compatibility (existing config files without these fields still work).
